# Google Sheets integration

This folder contains the Google Apps Script endpoint for CSS Playground submissions.

## Data collected

The `Pengumpulan` sheet uses these columns:

| Column | Field | Description |
|---|---|---|
| A | Nama | Name entered by the student |
| B | Tugas | Task number and title |
| C | Waktu Pengumpulan | Timestamp generated by Apps Script |
| D | Kode CSS / Jawaban Siswa | Exact CSS currently in the editor |
| E | Status Jawaban | `LULUS` or `PERLU PERBAIKAN` |
| F | Kriteria Lolos | Number of criteria passed |
| G | Total Kriteria | Number of criteria checked |
| H | Nilai (%) | Percentage calculated on the server |
| I | Rincian Penilaian | JSON with each criterion, pass/fail result, and feedback |

The submission also contains a temporary receipt ID used only to prevent duplicate rows and confirm delivery. It is not stored in the sheet. Browser local progress and other unrelated information are not sent.

The app requires students to click **Periksa Jawaban** after their latest code edit before they can submit. This ensures the saved CSS and score refer to the same version of the code.

## 1. Create or upgrade the spreadsheet

1. Open [Google Apps Script](https://script.google.com/).
2. Open the Apps Script project that you created for CSS Playground, or create a new one.
3. Replace the contents of its script file with the complete contents of `Code.gs` from this folder.
4. Save the project.
5. Select the function `setup` and click **Run**.
6. Grant the requested Google Sheets permissions.
7. Open **Execution log**. The generated spreadsheet URL is printed there.

The `setup()` function creates the spreadsheet and the `Pengumpulan` tab automatically. Running it again reuses the same spreadsheet and updates the header to nine columns. The original columns A-C remain in place so existing name, task, and timestamp rows are not shifted.

## 2. Deploy as a web app

1. In Apps Script, click **Deploy → Manage deployments**.
2. Edit the existing web app deployment, or create a **New deployment** if none exists.
3. Select type **Web app**.
4. Set **Execute as** to **Me**.
5. Set **Who has access** to **Anyone** so students can submit without signing in.
6. Deploy, authorize if requested, and copy the web app URL. It should end with `/exec`.

After changing `Code.gs`, select **New version** when editing the deployment. The URL normally remains the same when editing an existing deployment.

## 3. Configure CSS Playground

In the repository's `index.html`, find:

```js
const GOOGLE_SHEETS_WEB_APP_URL = 'PASTE_APPS_SCRIPT_WEB_APP_URL_HERE';
```

Replace the placeholder with the deployed web app URL, for example:

```js
const GOOGLE_SHEETS_WEB_APP_URL = 'https://script.google.com/macros/s/DEPLOYMENT_ID/exec';
```

Commit the change to `main`, then reload CSS Playground.

## 4. Student submission flow

1. Student selects a task and writes CSS.
2. Student clicks **Periksa Jawaban**.
3. Student opens **Kirim Jawaban**, enters their name, and submits.
4. The browser sends the name, task, CSS source, and criterion results.
5. Apps Script validates the score against the individual criterion results and calculates the percentage on the server.
6. Apps Script generates the timestamp and writes the row to Google Sheets.
7. The browser shows success only after the Apps Script receipt is confirmed.

The browser sends JSON as `text/plain` to avoid a CORS preflight, then checks a short-lived receipt using JSONP. If the browser reports that submission could not be confirmed, check Apps Script **Executions** and the Google Sheet before asking the student to retry. A network interruption can occur after the server has already appended the row.

## Privacy and limitations

- The sheet now stores the student's CSS source and the checker result. Treat the spreadsheet as student assessment data and share it only with authorized teachers.
- The code length is limited to 45,000 characters per submission to stay below Google Sheets cell limits.
- The percentage is calculated by Apps Script from passed and total criteria. The submitted per-criterion results are also stored for review.
- The endpoint is public and is not an identity-verification mechanism. Names are self-reported and can be spoofed. For higher-trust assessment, add student authentication or a server-validated class access code.
- The server generates the submission time using the `Asia/Jakarta` timezone.
